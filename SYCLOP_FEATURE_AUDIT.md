# Syclop / Syncler feature audit

Audit date: 2026-10-24. Syclop base: NuvioTV `b36db80`, plus the applied Syclop source changes in the maintainer workspace. Publication and installed-artifact state are tracked separately. This is a source audit, not a claim that every feature has passed account or TV testing. No device changes or private Syncler account data were used for this audit.

**Connected-service-only policy in source:** Local P2P is disabled by immutable player/backend guards, and packaging excludes the local torrent-engine library. Playback requires a private, expiring, exact-URL HTTPS grant from Syclop's authenticated native debrid resolver or connected cloud library, bound to the initiating viewer/account; cached links cannot acquire a new viewer's authority. Guards also cover Exo/MPV, external-player and browser entry points. Downloaded executable JavaScript/Cloudstream DEX plugins are disabled, including stored/cached providers and direct test/load routes. Declarative Express/Magnify and Stremio JSON discovery remain, but their supplied URLs alone cannot authorize playback. The combined optimized build passed 690 focused tests and APK inspection confirmed the local torrent-engine library is absent. The resulting build is installed on the Shield; real decoded playback acceptance remains open. This is not a packet-capture claim. Executable-plugin and arbitrary direct-URL compatibility are intentionally restricted because unverifiable code or URLs could bypass the requested service-only path.

Syclop does **not yet have all Syncler functionality**. It now includes a bounded Express adapter, native RD/AD device login, MAL catalogs/Library controls, Trakt manual actions, Simkl V2 authorization code and portable local backups. Arbitrary provider compatibility, cross-catalog anime identity, remaining account verification, restricted profiles and casting still have material gaps.

## Transport evidence and acceptance boundary

The sanitized playback evidence inspected by the parent contained an **HTTPS** AllDebrid download URL. Earlier “HTTP” shorthand described the HTTP family and is not evidence of an insecure URL or of a transport-policy failure. The [official AllDebrid API](https://docs.alldebrid.com/#download-link) requires HTTPS API calls but includes both HTTP download examples and an HTTPS streaming example; its unlock/streaming/delayed parameter lists expose no documented HTTPS-selection flag. This does not establish the default frequency or current behavior for every file. The applied grant policy accepts HTTPS only, so general compatibility with an authenticated HTTP result remains unverified. No undocumented parameter or URL scheme rewrite has been added. Successful decoded playback remains a separate acceptance gate.

## MyAnimeList registration and remaining verification

This is **one developer registration owned by Syclop's maintainer**, not a developer registration required from every Syclop user. Ordinary users use Connect and authorize their own MAL accounts. Do not copy Syncler/Nuvio client credentials or put MAL passwords, authorization codes or tokens in this document.

The [official MAL authorization reference](https://myanimelist.net/apiconfig/references/authorization) requires a pre-registered redirect matching the authorization request. It documents PKCE with the `plain` method and supports clients without a client secret. The native implementation generates a fresh verifier/state, validates the exact callback, keeps access/refresh tokens encrypted per profile and does not bundle a client secret.

Maintainer steps:

1. The owner reports successful Syclop registration in [MAL API configuration](https://myanimelist.net/apiconfig) and supplied public Client ID `76daded66e7bb55596834840c1d73ebd`. This is owner-reported registration evidence, not a completed native OAuth exchange. The authenticated form's exact app-type selection was not independently inspected by this audit.
2. The configured redirect is `https://dintalframe.github.io/Syclop/mal/`, including its trailing slash. The page has been deployed and verified live. Native relay support is restricted to this exact URI. Public state carries only a fresh nonce/current private IPv4 LAN return URI, with no verifier or tokens. The page requires a user gesture to return code/state to the TV; token exchange still uses the registered HTTPS redirect.
3. The active TV listener uses `http://<current-private-IPv4>:17893/mal/callback` only during the five-minute attempt. The authorizing phone must reach the TV on that network. The native app validates exact state, destination and active profile; manual paste of the registered HTTPS callback remains available. A fixed per-TV LAN URI can be used in advanced configuration only if the owner separately registers it; MAL's public docs do not confirm private HTTP acceptance, and that mode is not suitable for general distribution.
4. Public client ID/redirect configuration is embedded in the installed first optimized release; the [copyable public fields](SYCLOP_APP_REGISTRATION.md) are separate from account credentials and signing material. Build defaults remain blank when configuration is omitted, and an older installed APK does not acquire new build values automatically. Device developer overrides remain available. Ordinary users connect their own accounts without registering an app; no client secret is embedded.
5. The current source hoists authorization out of lazy-list recycling and pauses ambient dismissal only for a live attempt. It retires the listener/session intentionally on cancel, expiry or viewer change, commits before Connected and rejects stale same-profile reconnect/refresh results. These lifecycle/persistence fixes await a fresh successful account round trip; phone approval alone is not proof of stored native connection.
6. Confirm the [official API v2](https://myanimelist.net/apiconfig/references/api/v2) list read, manual list edit, refresh and one known-ID completion write using the owner's test account. Also test denied consent, wrong state, expired session, profile switching and cancel while exchanging. The current callback/config rules have focused unit tests, but no registered-account success is claimed by this audit.

## Audit boundary

It is not a promise of bit-for-bit Syncler behavior, access to its private backend, compatibility with every provider, or completion of all future features.
