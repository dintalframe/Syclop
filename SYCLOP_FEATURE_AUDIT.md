# Syclop / Syncler feature audit

Audit date: 2026-10-24. Syclop base: NuvioTV `b36db80`, plus the Syclop source changes published on branch `syclop`. This is a source audit, not a claim that every feature has passed account or TV testing. No device changes or private Syncler account data were used for this audit.

Syclop does **not yet have all Syncler functionality**. It now includes a bounded Express adapter, native RD/AD device login, MAL catalogs/Library controls and portable local backups. Arbitrary provider compatibility, cross-catalog anime identity, remaining account verification, restricted profiles and casting still have material gaps.

## Evidence and status

- **Implemented—unverified:** an actual code path exists; this audit did not complete its real account/playback/device acceptance test.
- **Partial:** a useful subset exists, with the material difference stated.
- **Missing:** no equivalent implementation was found in the examined source.
- **Host-tested** records focused JVM/protocol tests, not live service-account or Shield acceptance. This update reconciles implementation and integration evidence already supplied by the parent task; it does not rerun tests or change the device.
- Syncler resource evidence refers to the locally inspected decoded English resources (maintainer workspace only; no decompiled source is included in this fork) by stable hex resource ID. Resources can include old or unused screens; they establish that a feature is represented, not that every retained string describes current behavior. No decompiled implementation or proprietary provider definitions were copied.
- Official sources: [current feature overview](https://beta.syncler.net/), [established feature overview](https://app.syncler.net/), [provider development](https://support.syncler.net/develop/source-provider-package), [personalized Home](https://support.syncler.net/personalize/create-personalized-home-screen), [restricted accounts](https://support.syncler.net/personalize/restricted-accounts), and [Debrid suite](https://app.syncler.net/plus). The current and established sites describe different release generations; the table does not assume they are identical.

All Syclop paths below are relative to `app/src/`; `main/java/` paths share the prefix `com/nuvio/tv/`.

## Priorities and acceptance gates

1. **P0: verify usable sources without credential leakage.** Exercise the implemented Express subset/user-selected add-on with one movie, one episode and one season pack, preserving hash/file identity through native resolve. Keep debrid credentials on-device and send them only to that service. Paid service subscriptions remain separate from Syclop app pricing; arbitrary provider compatibility and redistribution rights are not implied.
2. **P0: verify real account flows.** Trakt registration and viewer login are verified; RD/AD approved-user Connected status is also verified on the Shield. MAL registration is owner-reported successful and its public configuration is embedded in the installed first optimized release. Real refresh/reconnect/cancel/sign-out, MAL account/catalog/write paths and Simkl configuration still need verification. Unit/protocol tests do not substitute for these round trips. See [application registration](SYCLOP_APP_REGISTRATION.md).
3. **P0: anime identity and English dub acceptance.** Establish season-specific cross-IDs and absolute numbering with explicit fixtures (specials, split cours, later seasons, movie and remakes). Never convert a title similarity into a watched write. Verify the chosen source actually offers English audio and that the player selects it.
4. **P1: verify MAL library semantics.** Exercise Home/list/search catalogs, shared Library status changes, exact-ID episode navigation, score/rewatch edits, disconnect/reconnect and profile switching. Add a bounded retry/outbox before claiming full parity. Official MAL metadata carries no IMDb mapping; the Express bridge uses verified title/year/entry episode only where supported. MAL episode counts are not timestamp resume positions.
5. **P1: persistence and family use.** Verify the implemented, explicitly scoped portable backup on the Shield: picker or Downloads fallback, preview, queued cold start, disconnect behavior and Undo. Keep excluded private providers/settings visible in the instructions. Local PIN/restricted-content rules and co-viewer tracking remain separate gaps; cross-device sync is not implemented.
6. **P1: playback parity tests.** Test autoplay/AutoNext with internal and Just Player paths; exact file selection; subtitle/audio defaults; filtering unknown facts; network failure; resume and source failure recovery. Add only measured capabilities to user-facing claims.
7. **P2: optional integrations.** Implement casting, Orion, Kodi network control or remaining management/rating/check-in functions only after their desired workflows and public API contracts are specified. Keep a visible gap list rather than labelling the fork complete.

## MyAnimeList registration and remaining verification

This is **one developer registration owned by Syclop's maintainer**, not a developer registration required from every Syclop user. Ordinary users use Connect and authorize their own MAL accounts. Do not copy Syncler/Nuvio client credentials or put MAL passwords, authorization codes or tokens in this document.

The [official MAL authorization reference](https://myanimelist.net/apiconfig/references/authorization) requires a pre-registered redirect matching the authorization request. It documents PKCE with the `plain` method and supports clients without a client secret. The native implementation generates a fresh verifier/state, validates the exact callback, keeps access/refresh tokens encrypted per profile and does not bundle a client secret.

Maintainer steps:

1. The owner reports successful Syclop registration in [MAL API configuration](https://myanimelist.net/apiconfig) and supplied public Client ID `76daded66e7bb55596834840c1d73ebd`. This is owner-reported registration evidence, not a completed native OAuth exchange. The authenticated form's exact app-type selection was not independently inspected by this audit.
2. The configured redirect is `https://dintalframe.github.io/Syclop/mal/`, including its trailing slash. The page has been deployed and verified live. Native relay support is restricted to this exact URI. Public state carries only a fresh nonce/current private IPv4 LAN return URI, with no verifier or tokens. The page requires a user gesture to return code/state to the TV; token exchange still uses the registered HTTPS redirect.
3. The active TV listener uses `http://<current-private-IPv4>:17893/mal/callback` only during the five-minute attempt. The authorizing phone must reach the TV on that network. The native app validates exact state, destination and active profile; manual paste of the registered HTTPS callback remains available. A fixed per-TV LAN URI can be used in advanced configuration only if the owner separately registers it; MAL's public docs do not confirm private HTTP acceptance, and that mode is not suitable for general distribution.
4. Public client ID/redirect configuration is embedded in the installed first optimized release; the [copyable public fields](SYCLOP_APP_REGISTRATION.md) are separate from account credentials and signing material. Build defaults remain blank when configuration is omitted, and an older installed APK does not acquire new build values automatically. Device developer overrides remain available. Ordinary users connect their own accounts without registering an app; no client secret is embedded.
5. Confirm the [official API v2](https://myanimelist.net/apiconfig/references/api/v2) list read, manual list edit, refresh and one known-ID completion write using the owner's test account. Also test denied consent, wrong state, expired session, profile switching and cancel while exchanging. The current callback/config rules have focused unit tests, but no registered-account success is claimed by this audit.

## Audit boundary

This document covers the requested feature groups and material gaps. It is not a promise of bit-for-bit Syncler behavior, access to its private backend, compatibility with every provider, or completion of all future features. Syncler static resources were used only to identify capabilities. The initial audit changed no production code; the MAL catalog rows above were updated after the separately authorized native catalog patch. Account/device acceptance belongs in the main build and verification record.
