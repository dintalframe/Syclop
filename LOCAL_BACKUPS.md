# Local backups

Open **Settings → App → Local backup and restore**. Choose a destination on the TV or attached storage with Android's document picker. If the Shield has no picker, **Save on this TV** writes to `Downloads/SyclopBackups/` on Android 10 or newer; the dialog also lists accessible backups from that folder. Older Android versions use the app's external Downloads folder, which is removed when the app is uninstalled. Copy important files to separate storage.

A `.syclop` file contains a versioned manifest and JSON payload in a ZIP. It includes all local profiles, supported appearance/layout/player/track preferences, local Library items, watched history and resume positions. Only these public provider configurations are included: Magnify Full, Cinemeta and OpenSubtitles. Private add-on URLs, service credentials, OAuth state, plug-in code/configuration, profile PINs, remote/custom image URLs, artwork URLs and playback diagnostics are excluded. This is a supported local-data backup, not a complete copy of every upstream setting or a cloud synchronization feature. Files include viewing history and profile names; protect them accordingly.

Stream sorting and source-filter preferences in `debrid_settings`, including the per-profile `stream_bitrate_order_v1` and `stream_size_order_v2` migration markers, are excluded together. A restored profile receives the current bitrate/resolution/file-size default migration; any later explicit Original/custom source order must be selected again. This avoids carrying a completed migration marker without its matching sort preference.

First-use tracking initialization markers and provider account caches are not exported. Reconnecting after restore performs the applicable account import again; a completed initialization marker is not a portable history backup.

Select a file to see its date and profiles before making changes. **Queue restore** replaces all current local profiles and their data stores on the next cold start and disconnects all service accounts. Add private providers and plug-ins again, then reconnect accounts. Public Syclop application registrations remain on the TV, so viewers do not need developer credentials. Library and progress sources switch to local data. This deliberately prevents an imported profile ID from inheriting another person's existing account tokens.

After queuing, choose **Close app, then reopen** and launch Syclop again. Until the app closes, **Cancel queued operation** removes the request without applying it. Backup creation and restore are refused while any profile PIN lock is enabled; turn off locks through the normal authenticated profile settings first. The app never imports or bypasses a PIN.

Before the first live store is replaced, the app stages validated data and checks that the current state fits a bounded private recovery snapshot. It swaps the DataStore, SharedPreferences and Continue Watching enrichment directories before Android initializes their readers. The original directories, including encrypted account stores, stay only inside this installation's private `noBackupFilesDir` for automatic rollback and **Undo previous restore**. They are never exported. Android Keystore keys stay on the device. Undo does not survive uninstalling Syclop, clearing its data, or transferring the portable file to another device. A completed later restore or Undo replaces the previous recovery snapshot.

The archive reader rejects foreign application IDs, unsupported schema versions, duplicate/unexpected ZIP members, path traversal, invalid UTF-8/JSON, incompatible preference types and out-of-bounds values. Compressed and payload sizes are limited to 16 MiB. SHA-256 plus ZIP CRC detect corruption; they do not prove who created a file. The private recovery transaction is limited to 128 MiB, 1,024 flat entries per directory and 32 MiB per file. An oversized original state is rejected before mutation, preserving the Undo guarantee. An invalid queued file is rejected so intact current stores can still open; an interrupted mixed-state transaction must recover successfully before normal startup continues.

The JVM tests cover portable profile/library/watched/progress round trips, credential/private-URL exclusion, public-provider matching, archive corruption/type/schema rejection, reused profile IDs, directory-swap failure and simulated post-swap process death, private credential rollback/Undo, corrupt queues, queued-Undo cancellation and recovery-size limits. It verified Library/history/resume, local sources, private-sentinel exclusion/removal/recovery, preserved public registration, distinct processes and fixture-owned publication cleanup. This evidence applies to that APK; it does not qualify later changes. Earlier Shield checks verified export, picker launch and canonical/legacy backup previews; those previews were cancelled without replacing data. Host tests and the emulator fixture do not establish those UI/storage/account behaviors or authorize replacing household data.
